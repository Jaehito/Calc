# 지출 기록 — 잠금화면에서 Notion으로

안드로이드 잠금화면 알림에 `커피 4500` 을 입력하면 Notion 지출 DB에 한 줄이 추가되고,
**오늘 쓸 수 있는 돈**이 그 자리에서 돌아옵니다. 잠금 해제가 필요 없습니다.

곳간은 **개인**과 **공용** 둘이고 서로 섞이지 않습니다. DB도 따로 씁니다.

```
잠금화면 알림 ──[기록]──▶ 인라인 답장 입력 ──▶ 파싱 ──▶ Notion API ──▶ DB 한 줄
```

## 구성

| 경로 | 역할 |
|---|---|
| `android/` | 안드로이드 앱 (Kotlin) |
| `notion_expense.py` | PC에서 연동을 확인·기록하는 CLI (설치 불필요) |

앱 소스 (`android/app/src/main/java/com/calc/expense/`):

| 파일 | 역할 |
|---|---|
| `ExpenseParser.kt` | `커피 4500` → `Expense("커피", 4500)` |
| `Purse.kt` | 곳간 종류와 기본 이름 |
| `Payday.kt` | 월급날 기준 예산 주기 계산 (순수) |
| `Budget.kt` | 곳간 정산 — 순수 계산, Android 의존 없음 |
| `Ledger.kt` | 곳간·캐시·Notion을 잇는 유일한 진입점 |
| `SpendingCache.kt` | 날짜별 지출 로컬 사본 (Notion이 진실, 이건 파생) |
| `BudgetStore.kt` | 곳간 앵커 저장 |
| `StatusText.kt` | 알림·현황 문구 조립 (순수) |
| `NotionIds.kt` | 붙여넣은 URL에서 DB ID 추출 |

| `MainActivity.kt` | 설정 화면 |

## 1. Notion 준비

**토큰 발급**
1. https://www.notion.so/my-integrations → **New integration** → Internal
2. **Internal Integration Secret** 복사

**DB 두 개 만들기** — 개인용 하나, 공용 하나

곳간이 둘이므로 DB도 둘입니다. 공용 계좌가 아직 없으면 **개인 것만 먼저** 만들어도 됩니다 — 공용은 나중에 앱 설정에 채우기만 하면 됩니다.

개인 DB를 공용과 나누는 이유는 프라이버시가 아니라 **데이터 품질**입니다. 전부 공개되면 설명하기 싫은 지출을 안 적게 되고, 그러면 기록이 조용히 왜곡됩니다.

**각 DB에 권한 주기** — 이걸 빼먹으면 404가 납니다
- 지출 DB 페이지 → 우측 상단 `•••` → **연결(Connections)** → 만든 인테그레이션 추가
- **DB 두 개 모두** 해야 합니다. 인테그레이션(토큰)은 하나로 충분합니다.

**DB 속성** — 아래 세 가지가 있어야 합니다. 이름은 자유롭게 바꿔도 되고, 앱 설정에 그 이름을 적으면 됩니다.

| 기본 이름 | 타입 |
|---|---|
| 이름 | `title` |
| 금액 | `number` |
| 날짜 | `date` |

**DB는 하나로 두세요.** 달마다 새 DB를 만들면 매달 앱 설정을 고쳐야 하고, 곳간이 달을 넘나들며 계산할 때 지난달을 읽지 못합니다. 데이터는 DB 하나에 모으고, 월별로 보고 싶으면 뷰를 나눕니다.

| 뷰 | 설정 |
|---|---|
| 이번 달 (기본) | 날짜 필터 `이번 달`, 날짜 내림차순 |
| 월별 | 날짜 기준 그룹화 |
| 전체 | 필터 없음 |

위 세 속성 외에 카테고리·결제수단·메모 같은 열을 더 두어도 앱은 무시합니다. 노션에서 보기 위한 열은 자유롭게 추가하세요.

## 3. 앱 설정

1. 앱 실행 → **인테그레이션 시크릿** 입력 (두 DB가 같은 토큰을 씁니다)
2. 속성 이름 3개 확인 — DB의 **열 이름**과 같아야 합니다 (제목 열이 `제목`이면 `제목`)
3. **예산 주기** → 월급날 (1~31). 달력 월로 쓰려면 `1`
4. **개인 곳간** → 이름 · DB ID · 예산 (`930000` 도 `93만` 도 됩니다)
5. **공용 곳간** → 아직 공용 계좌가 없으면 **비워 두세요**
6. **저장하고 연결 확인** → 연결된 곳간마다 DB 제목이 뜨면 성공
7. **알림 켜기** → 알림 권한 허용

DB URL을 통째로 붙여넣어도 ID만 뽑아냅니다.

화면 맨 위에 곳간마다 오늘 쓸 수 있는 돈이 표시됩니다. 앱을 열 때마다 Notion을 다시 읽어 맞춥니다.

## 4. 사용

잠금화면 알림의 **기록** 을 누르고 입력합니다.
곳간을 둘 다 연결했다면 버튼이 **개인** / **공용** 두 개로 갈립니다 — 타이핑은 그대로고 누르는 위치만 다릅니다.
하나만 연결했으면 고르게 하지 않습니다.



| 입력 | 결과 |
|---|---|
| `커피 4500` | 커피 / 4,500원 |
| `점심 김밥 6000` | 점심 김밥 / 6,000원 |
| `4500 커피` | 커피 / 4,500원 |
| `택시 12,000원` | 택시 / 12,000원 |
| `커피 4천` | 커피 / 4,000원 |
| `장보기 1.5만` | 장보기 / 15,000원 |

규칙은 **마지막 숫자 토큰이 금액, 나머지가 이름**입니다.

결과는 같은 알림에 바로 돌아옵니다.

```
✓ 커피 4,500 · 오늘 쓸 수 있는 돈 41,000     ← 잠금화면 (접힌 상태)

✓ 커피 4,500원 기록됨 · 오후 3:21            ← 펼쳤을 때
오늘 쓸 수 있는 돈 41,000원
하루치 30,000 + 곳간 23,400 − 오늘 12,400
```

## 5. 곳간

곳간의 **이름은 자유롭게 정할 수 있습니다.** «재호 용돈», «우리집» 처럼요 — 알림 버튼과 현황에 그 이름이 그대로 나옵니다. 비워 두면 «개인» · «공용» 을 씁니다. 잠금화면 버튼 두 개가 한 줄에 들어가야 해서 8자까지만 받습니다.

곳간은 **둘**이고 **서로 섞이지 않습니다.** 공용에서 크게 초과해도 개인 하루치는 1원도 줄지 않고, 반대도 마찬가지입니다. 섞기 시작하면 "네 용돈에서 얼마 내"가 앱 안으로 들어옵니다. 공용이 모자라면 공용 하루치가 남은 날 동안 줄어들 뿐이고, 그걸 어떻게 할지는 대화로 정하는 겁니다.

아래 규칙은 곳간마다 독립적으로 돕니다.

### 주기는 월급날부터

예산은 **월급날을 경계로** 리셋됩니다. 25일이면 25일부터 다음 달 24일까지가 한 주기이고, 그 마지막 날(24일)이 **목표일**입니다. 달력 1일 기준으로 쓰려면 월급날에 `1`을 넣으세요.

달력 1일이 아니라 월급날을 쓰는 이유는 실제로 돈이 그렇게 들어오기 때문입니다. 25일에 받는데 1일에 리셋되면, 매달 24일까지는 지난달 돈으로 이번 달 예산을 쓰는 셈이 됩니다.

기록하면 두 가지가 돌아옵니다.

```
오늘 쓸 수 있는 돈 41,000원          ← 지금 괜찮은가
9월 24일까지 542,400원              ← 이 페이스로 가도 되는가
 · 남은 22일 (하루 24,654)
```

### 하루치와 곳간

예산을 그 주기의 일수로 나눈 값이 **하루치**입니다. 하루치를 다 안 쓰면 남은 만큼이 **곳간**에 쌓이고, 다음 날 쓸 수 있는 돈이 그만큼 늘어납니다. 절약의 보상이 월말이 아니라 다음 날 아침에 옵니다.

넘겼을 때는 비대칭으로 처리합니다.

```
곳간 += 하루치 − 그날 지출

곳간이 음수가 되면
    모자란 만큼만 그 주기 남은 날에 나눠 하루치를 낮춘다
    곳간은 0 으로
```

곳간이 먼저 흡수하기 때문에 크게 쓴 다음 날에도 "오늘 쓸 수 있는 돈"이 음수로 남지 않습니다. 마이너스 잔고는 계획이 아니라 판결문이라 앱을 안 열게 만듭니다.

월급날이 오면 하루치가 원래대로 돌아가고, 곳간은 **하루치 5일분까지만** 다음 주기로 넘어갑니다. 무한히 쌓여 예산이 무의미해지는 것과, 주기 끝에 "어차피 사라지니 쓰자"가 되는 것을 둘 다 막습니다.

곳간은 Notion에 없고 앱에만 있습니다. 앱을 지우면 곳간은 0부터 다시 쌓입니다 — 과거를 소급해 복원하지 않습니다.

**적지 않으면 곳간이 부풀어 숫자가 거짓말을 합니다.** 이건 버그가 아니라 의도한 손해입니다. 앱이 잔소리하는 대신, 안 적으면 내 도구가 나에게 쓸모없어집니다.

## 6. 삼성(One UI) 확인 사항

인라인 답장 자체는 표준 API지만, One UI는 기본 설정이 잠금화면 내용을 가립니다.

- **설정 → 알림 → 잠금화면 알림** → *내용 표시* 켜기
- **설정 → 알림 → 고급 설정 → 알림 아이콘만 표시** 끄기
- **설정 → 배터리 → 백그라운드 사용 제한** 에서 이 앱을 **제한 안 함**으로 (절전 모드가 알림을 죽입니다)

그래도 답장 칸을 눌렀을 때 잠금 해제를 요구한다면, 그건 기기 정책이라 앱에서 우회할 수 없습니다.
지문 한 번 찍고 입력하는 형태가 됩니다.

## 7. 문제 해결

| 증상 | 원인 |
|---|---|
| `401` | 토큰이 틀렸습니다 |
| `403` / `404` | DB의 `•••` → 연결 에 인테그레이션을 추가하지 않았습니다 |
| `속성이 DB에 없습니다` | 앱에 적은 속성 이름과 실제 DB 이름이 다릅니다 |
| `... 은 number 이어야 하는데 rich_text 입니다` | 금액 속성 타입을 숫자로 바꾸세요 |
| `시간 초과` | 요청이 Notion에 닿았는지 알 수 없습니다. DB를 확인하고 없으면 다시 입력하세요 |
| 재부팅 후 알림 사라짐 | 배터리 최적화에서 앱을 제외하세요 |
| 평문 저장 경고가 뜸 | 기기 키스토어 문제. 앱 전용 저장소라 다른 앱은 못 읽지만, 루팅 기기라면 주의하세요 |

## 보안

- 토큰은 `EncryptedSharedPreferences`(AES-256)로 저장하며, 기기 키스토어 초기화에 실패하면 앱 전용 평문 저장으로 내려앉고 설정 화면에 경고를 띄웁니다.
- `ReplyReceiver` 는 `exported=false` 라 다른 앱이 호출할 수 없습니다.
- 디버그 서명 APK입니다. 배포용이 아니라 개인 사용 목적입니다.
