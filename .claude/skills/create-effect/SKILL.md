# 전투 이펙트 제작

이 문서는 **다시 알아내면 비싼 것들**을 모아 둔다. 특히 §아트 레퍼런스와 §블룸 안전 규칙은 어겼을 때 화면이 조용히 망가지므로 먼저 읽는다.

## 아트 레퍼런스 (SSOT — 이펙트 색·형태의 기준)

⚠️ **현재 `BattlePrototype`(녹색 펠트 + 두꺼운 금색)은 구 아트다.** 이펙트는 **아래 신 아트 방향**에 맞춘다. 신 아트 화면은 2026-08-26 기준 **프로젝트 씬에 아직 없다**(레퍼런스 스크린샷만 존재). 씬이 들어오면 실제 에셋에서 색을 다시 뽑아 이 절을 갱신한다.

**팔레트** (스크린샷 육안 추정값 — 에셋에서 추출한 값이 아니다)

| 역할 | 근사값 |
|---|---|
| 배경 와인/버건디 | `#3A0E1A` ~ `#4A1020`, 깊은 곳 `#2A0912` |
| 금색 선·프레임 | `#C9A961` (두껍지 않고 **가는 선**) |
| 크림 패널·말풍선 | `#F5E6DE` ~ `#D9C7B8` |

### 불변 제약 (스타일이 바뀌어도 유지 — 이건 취향이 아니다)

1. **명도 대비로 승부한다.** 배경이 와인레드라 **주황~금 계열은 색상(hue)이 겹쳐** 묻히고 기존 금색 필리그리와 싸운다. 밝은 쪽(크림·흰·창백한 금)이 안전하다. 다른 색을 쓰고 싶으면 **와인 위에서 명도가 확실히 뜨는지**를 기준으로 고른다.
2. **캐릭터 얼굴을 덮지 않는다.** 캐릭터 아트가 셀링포인트다. 중앙을 비우거나 착탄점을 아래로 오프셋한다.
3. **선화·판화(engraving) 미학과 충돌하지 않는다.** 잉크 라인워크, 얇은 이중 테두리, 가는 금선이 이 화면의 언어다. 부드럽고 흐릿한 덩어리만으로 채우면 이질적이다 — **날카로운 요소가 최소 하나는 있어야 한다.**
4. **톤은 절제.** 격렬한 폭발보다 짧은 섬광 → 빠른 소멸. 지속 0.3초 안팎.
5. **블룸 안전선을 지킨다** (§블룸 안전 규칙). 밝은 항만 HDR 1.0 초과.
6. **§싸구려로 보이는 원인 체크리스트를 통과해야 한다.** 어떤 스타일이든 시차·크기 이질성·온도 램프는 적용된다.

### 스타일은 고정하지 않는다 — 카탈로그에서 고른다

⚠️ **이전 판의 이 문서는 "완결된 원 금지 → 끊어진 호", "색은 크림 확정" 을 하드 규칙으로 박아 스타일을 하나로 못 박았다. 그건 취향이지 제약이 아니다.** 형태 언어는 **고르는 것**이고, 아래는 이 게임(블랙잭·카지노 느와르 + 판화 아트)에 맞는 후보다.

**새 이펙트를 만들 때는 하나를 골라 바로 만들지 말고, 2~3안을 제시해 사용자가 고르게 한다.**

| 스타일 | 성격 | 구현 | 신규 아트 |
|---|---|---|---|
| **① 방사 버스트 — 현재·추천** | 끊어진 호 + 테이퍼 파편 + 온도 램프. 범용이라 어떤 데미지 원인에도 맞는다 | 구현 완료 (프리팹 10시스템) | 불필요 |
| **② 단검 관통** | 방향성. 진입선 섬광 → 수직 부채꼴 충격파 → **후방 편향** 파편 → 꽂힌 칼 진동. **원인이 화면에 보인다**(§싸구려 7번 정면 처방) | 중. 토대 있음 — `_numberIconImage` 칼 아이콘 160px, `DamageFlightCurve` 도착 접선 | 칼 실루엣(절차적 가능, 손그림이 더 좋음) |
| **③ 베기 궤적(슬래시)** | 화면을 가로지르는 호 1~2개. 아주 짧고 날카롭다. **선화 미학과 가장 잘 맞고 가장 싸다** | 낮음. 셰이더 1장으로 충분 | 불필요 |
| **④ 카드 파열** | 카드가 산산조각. 직사각형 파편이라 **다른 게임과 안 겹치는 고유 어휘** | 중. 파편 메시가 사각형 | 카드 뒷면은 이미 있음 |
| **⑤ 수트 문양 각인** | 착탄점에 스페이드·하트가 **각인되듯** 번쩍였다 사라짐. 판화 미학 정면 | 낮~중 | 수트 실루엣(절차적 가능) |
| **⑥ 금박 파열** | 금박이 벗겨져 흩날림. 팔레트와 완벽 일치, 고급스러움 | 중. 얇은 판 파편 + 회전 | 불필요 |
| **⑦ 칩 튕김** | 소울칩·포커칩이 튀어오름. 카지노 어휘, 물리감 | 중. 물리 파편 | 칩 스프라이트 |

**섞어도 된다.** 예: ② 단검 관통 + ⑤ 수트 각인, ③ 슬래시 + ⑥ 금박. 티어별로 다른 스타일을 쓰는 것도 가능하다(하 = 슬래시, 상 = 단검 관통).

**①은 기본값일 뿐 정답이 아니다.** 새로 만들 때 ①을 자동으로 고르지 말고 카탈로그를 제시한다.

## 방식 결정 — 파티클이 기본, 셰이더는 절차적 형태 담당 (하이브리드)

**사용자 결정 (2026-08-26): 하이브리드로 가되 기본은 파티클.** 상 티어 착탄을 두 방식으로 각각 만들어 같은 진행률·같은 색·같은 지속으로 실측 비교한 결과다.

| 요소 | 담당 | 왜 |
|---|---|---|
| 파편·잔재·2차 스파크 | **파티클** | Trails 로 진짜 궤적이 남는다 |
| 얇고 선명한 확장 링·호 | **셰이더** | 텍스쳐 스케일업으로는 얇은 링이 원리적으로 불가 |
| 디스토션·디졸브·플로우 | **셰이더** | 화면 위치의 함수로만 되는 것 |
| 물리·충돌·화면 밖으로 나가는 것 | **파티클** | 셰이더 쿼드는 경계에서 클리핑된다 |

**결정적 근거 — Trails 는 프레임 간 상태가 필요하다.** 파티클의 파편은 *지나온 경로가 남은 것*이고, 셰이더의 파편은 *현재 위치에 그린 도형*이다. 셰이더 쿼드는 이전 프레임을 기억할 수 없으니 굵은 도형으로 길이감을 대신 낸다 → **"파편이 뭉툭하다"는 인상의 원인이 여기다.** 튜닝으로 좁혀지지 않는 차이다.

⚠️ **이 절은 한 번 틀렸다 — 같은 실수를 반복하지 마라.** 처음 이 문서는 "셰이더가 기본"을 권했다. 근거는 비용 구조(씬 무편집·diff·통일 강제)였고 그건 여전히 사실이다. **그런데 파티클을 최소 사양(3 시스템, 기본 모듈만)으로 방치한 상태로 비교했다.** 제대로 만들자 파티클이 이겼다.
- 에이전트는 셰이더를 더 잘 만든다(수학은 눈감고 검산되지만 파티클 15개 모듈의 상호작용은 창발적이다). **그 편향이 비교 결과를 만들 수 있다.**
- 비교 실험을 하려면 **양쪽을 같은 정성으로 만든 뒤에** 비교한다. 한쪽이 기준선/최소 사양이면 그건 실험이 아니다.

드로우콜은 선택 근거가 못 된다 — **ParticleSystem 은 시스템당 1 드로우콜로 배칭된다** (파티클 수만큼 늘지 않는다).

## 싸구려로 보이는 원인 (진단 체크리스트)

"이펙트가 무료 에셋 같다"는 피드백이 오면 이 순서로 본다. **1·2·3이 대부분을 만든다.**

| # | 증상 | 고치는 법 |
|---|---|---|
| 1 | **전부 동시 발화** — t=0에 링·파편·잔재가 같이 터져 한 덩어리로 읽힌다 | 층별 `startDelay` 시차: 섬광 0 → 호 0~0.06 → 중간 파편 0.03~0.08 → 미세 0.02~0.15 → 잔재 더 뒤 |
| 2 | **크기가 다 중간** — 크기 히스토그램이 평평한 것이 저렴함의 지문 | **극단적 이질성**: 큰 3개 + 중 12개 + 미세 45개. 계층을 **별도 시스템으로 분리**해야 따로 조정된다 |
| 3 | **색 온도 구배 없음** — 단색이면 "빛"이 아니라 "흰 조각"으로 읽힌다 | 5스톱 램프. 팔레트 안에서 가능: `(252,250,244) → (248,238,214) → (224,196,138) → (176,140,72) → (96,64,28)`. 계층별로 식는 속도를 다르게 |
| 4 | 모션 스트레치 부족 → 떠 있는 조각처럼 보인다 | 렌더러 `velocityScale` 상향 (0.014 → 0.03~0.04), Stretch 모드 |
| 5 | **대칭** — 90도 균등 배치, 완벽한 방사 대칭은 스톡 VFX의 지문 | 각도 완전 랜덤 + 반경 ±18% + 조각별 시차 |
| 6 | 미세 디테일 계층 없음 | 1~2px 짜리 45~60개, 수명 0.09~0.19s |
| 7 | **원인이 화면에 없다** — 뭐가 때렸는지 안 보이고 결과만 "팡" 터진다 | §남은 일의 단검 방향 참조 |

⚠️ **인스펙터 튜닝은 메뉴 재실행에 날아간다.** 프리팹이 `ImpactBurstParticlePrefabBuilder.cs`에서 코드로 구워지므로, 인스펙터에서 만진 값은 `Aftertime/SOS/Setup Impact Burst Assets` 를 다시 돌리면 덮어써진다. 만족한 뒤로는 메뉴를 돌리지 않거나, 튜닝값을 빌더 코드에 반영한다.

## 블룸 안전 규칙 (강함 — 어기면 UI가 통째로 번진다)

**현재 설정** (`BattlePrototype`, 2026-08-26 적용·실측 검증)

| 항목 | 값 |
|---|---|
| `BattleVolume` (씬 루트, layer **Default**) | `Volume` isGlobal, priority 0, `Assets/Settings/BattleVolumeProfile.asset` |
| 프로파일 내용 | **Bloom 단독**, threshold **1.4**, intensity **0.6** (둘 다 override ON) |
| 포스트프로세싱 | **`UICamera`(Overlay)에만 ON.** `Main Camera`(Base)는 OFF |
| 셰이더 HDR | `UIImpactBurst.mat` → `_HdrIntensity = 2.5` |

**포스트프로세싱은 `UICamera`에 켠다.** 전투 Canvas(`ScreenSpaceCamera`, planeDistance 1000)가 `UICamera`에 그려지고, URP 17.3은 포스트 패스를 **각 카메라의 `OnAfterRendering`** 에서 돌린다. Base(`Main Camera`)에 켜면 오버레이가 그려지기 **전에** 포스트가 끝나 아무것도 번지지 않는다.

**threshold를 1.36 아래로 내리지 마라.** URP 내부에 두 겹의 함정이 있다.

1. `PostProcessPassRenderGraph.cs` — 슬라이더 값이 `Mathf.GammaToLinearSpace()`로 **재매핑**된다
2. 같은 파일 — `thresholdKnee = threshold * 0.5f` (하드코딩 소프트 니) → **실효 차단 시작점이 `T/2`**

프로젝트는 **Linear** 컬러 스페이스라 UI 흰색은 linear 1.0이다. 흰 UI 누출:

| 슬라이더 | T(linear) | 니 시작 | 흰 UI 누출 |
|---|---|---|---|
| 1.0 | 1.000 | 0.500 | 12.5% |
| 1.15 | 1.376 | 0.688 | 3.54% |
| **1.3533** | 2.000 | 1.000 | **0 (최소 안전값)** |
| **1.4 (채택)** | 2.163 | 1.082 | 0 |

**세기가 부족하면 threshold를 내리지 말고 머티리얼 `_HdrIntensity`(1~8)를 올린다.** 이게 안전 속성을 지키는 유일한 조절 축이다.

⚠️ **`DefaultVolumeProfile.asset`의 Bloom은 지뢰다** — `active: 1`, threshold **0.9**, intensity **0**. 지금은 intensity 0이라 무해하지만 1.0 아래 threshold라, 누가 intensity를 올리면 `Title` 씬의 **거대한 크림 패널이 통째로 번진다** (Title은 포스트프로세싱이 켜져 있고 Volume이 없어 이 기본 프로파일을 그대로 받는다). 건드리지 않는다.

## 함정 (전부 실측으로 물린 것)

**셰이더**
- `fixed4`는 플랫폼에 따라 `[-2, 2]` 고정소수다 → HDR 출력이 잘린다. **`half4`를 쓴다.**
- HDR 증폭은 **밝은 항(코어·링 심·스파크)에만** 곱한다. 잔광·링 바깥까지 올리면 화면이 통째로 번진다. **RGB만** — 알파를 올리면 additive 블렌드가 깨진다.
- 시간을 셰이더에서 읽지 않는다(`_Time` 금지). C#이 `_Progress`를 트윈한다. 런타임 트윈은 `Ease.Linear`이므로 **프리뷰는 t를 보정 없이 그대로 넣는 것이 정확히 일치한다** — 이징을 흉내 내면 오히려 어긋난다.

**파티클**
- `main.scalingMode = ParticleSystemScalingMode.Hierarchy` **필수**. 기본값 Local이면 CanvasScaler가 UI를 줄일 때 파티클만 크기가 남아 해상도마다 어긋난다.
- URP에서 Built-in 파티클 셰이더는 **핑크**가 된다. `Sprites/Default`는 블렌드 프로퍼티를 노출하지 않아 머티리얼에서 additive로 못 바꾼다 → `ImpactParticleAdditive.shader`를 쓴다.
- `Simulate(restart: true)`는 호출마다 **재추첨**한다. 프리뷰에서 t별 비교를 하려면 인스턴스의 `randomSeed`를 고정한다(프리팹이 아니라 인스턴스에).
- 파티클 1 로컬 유닛 = 캔버스 1 px (Hierarchy 스케일 + 캔버스 자식). 크기가 작아 보인다고 `startSize`를 키우기 전에 **수명·확장 커브**를 먼저 본다 — Ring이 0.34초 선형이면 같은 진행률에서 0.28초 OutQuad인 Legacy보다 훨씬 작다.
- 에디트 모드 프리뷰 인스턴스는 `HideFlags.HideAndDontSave` + 종료 시 `DestroyImmediate`. 빠뜨리면 씬 저장에 잔재가 박힌다.

**에디터 리플렉션**
- `Volume`의 `isGlobal`·`priority`·`sharedProfile`은 **필드**다. `GetProperty`는 null을 돌려준다(`isGlobal`만 프로퍼티인 버전도 있으니 필드 우선 → 프로퍼티 폴백).
- `VolumeProfile.TryGet`은 오버로드가 있어 `GetMethod("TryGet")`이 **AmbiguousMatchException**을 던진다. `components` 리스트를 직접 훑는다.
- `EditorSceneManager.MoveGameObjectToScene`은 없다 → `SceneManager` 쪽.
- 씬을 열기 전 **열려 있는 씬의 dirty 상태를 확인한다.** dirty면 열지 않는다 — 아무도 앉아 있지 않은 에디터에 모달이 뜨면 멈춘다(`.claude/rules/playtest.md` §agent 인스턴스).

## 남은 일 (아직 안 한 것 — 착수 전 확인할 것)

- **단검이 꽂히는 방향성 연출** (사용자 제안, 2026-08-26). "원으로 팡 터지는" 것보다 **단검이 날아와 꽂히는** 느낌. 이것이 §싸구려 진단 7번(원인이 화면에 없다)을 정면으로 고친다 — 방사 대칭을 깨고 **진입 방향 벡터 하나가 전체를 지배**하게 만든다: 관통 섬광은 진입선을 따라 **선**으로, 충격파는 진입 방향에 수직인 **부채꼴**로, 파편은 **반대쪽으로 편향**, 꽂힌 칼이 0.1~0.2초 진동 후 페이드.
  - **토대가 이미 있다:** `DamageFlightEffectPlayer._numberIconImage` — 데미지 숫자 왼쪽에 **칼 아이콘이 160px**(`BattleHudLayout.DamageFlightIconSize`)로 함께 날아온다. 그 칼이 실제로 꽂히게 만드는 것이 자연스러운 확장이다.
  - **진입 방향도 이미 계산 가능하다:** `DamageFlightCurve.Evaluate(start, end, bulge, t, direction)` 의 도착 접선. 새 데이터가 필요 없다.
- **데미지 3티어** (`<20` / `20~21` / `>21` — 데미지 수치 기준, 사용자 확정). 상 티어에만 **화면 흔들림**. 방식과 무관한 작업이고 인프라가 이미 있다:
  - `BattleHitShakeMath.GetShakeOffset(elapsed, duration, **amplitude**)` — 진폭이 파라미터다. 새 코드가 아니라 다른 숫자를 넘기는 것. 결정적(난수 없음), EditMode 테스트 있음.
  - ⚠️ **카메라를 흔들면 아무 일도 안 일어난다** — 전투 캔버스가 Screen Space - Camera 라 캔버스가 따라붙는다(`BattleHitFeedbackPlayer.cs:8` 주석). 흔드는 대상은 **캔버스 하위 루트**다.
  - ⚠️ 기존 화면 흔들림은 **붉은 비그넷과 한 묶음**이다(플레이어 피격 표시). 큰 타격에 그대로 재사용하면 "내가 맞았다"는 반대 신호가 된다 → 비그넷 알파를 0으로 넘길 수 있는 경로가 필요하다.
  - 권장 진폭: 상 티어 화면 흔들림 **10~12px** (플레이어 피격이 16px인데 내가 때릴 때가 더 흔들리면 피격의 무게가 죽는다).
- **프리팹화.** 이펙트 1개 = 프리팹 1개, 루트에 `Play()` 하나만 노출하는 컴포넌트. 재생기는 내용물(셰이더냐 파티클이냐)을 모른다. 새 이펙트 = 프리팹 복제 → 인스펙터 재튜닝 → 필드 할당, **코드 0줄**. **하이브리드(셰이더 호 + 파티클 파편)의 전제조건이다.**
- **공용 HLSL include.** `SosCoreFlash` / `SosRing` / `SosSectorSparks` / `SosGlow` / `SosEase*` / `SosHash*` 를 한 파일에 모으면 새 이펙트가 조합 40줄로 끝나고, 톤 변경이 include 한 곳으로 전파된다. 이펙트가 2~3개 쌓인 뒤 추출하는 것이 설계 추측을 줄인다.
- **Legacy 스타일 제거.** 방식이 파티클로 확정됐으므로 `DamageFlightImpactStyle.Legacy` 경로를 정리할 수 있다. 비교 기준선으로 남겨둘 가치가 있는지만 확인하고 제거.
