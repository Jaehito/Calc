# Ask-first (구현 전)

> **이 파일이 SSOT.** Claude Code 전용 — `.cursor/**`·`AGENTS.md`는 읽지도 수정하지도 않는다(동기화 의무 없음).

## 원칙

- 플레이어가 느끼는 규칙·UI·레이아웃: **사용자 확인 전** 임의 구현 금지.
- **애매·충돌·미지·불명확** → `AskUserQuestion` 또는 Plan Mode. **추측·silent fallback 금지.**
- 질문이 2회 이상 필요하면 **1회 복합 `AskUserQuestion`**(복수 질문 포함)으로 병합해 턴 수를 줄인다.

## 구현 전 플랜 게이트 (= Plan Mode)

씬(`.unity`)·SO(`.asset`)·시각 작업(UI·레이아웃·연출)·Setup 변경은 **계획을 승인받은 후** 진행한다(플랜 게이트). 순수 코드·명확·소규모 변경은 Tier S로 간소화하되, 애매하면 Ask-first. **Tier 판정은 `CLAUDE.md` 워크플로가 SSOT.** 계획에는 다음을 포함한다:

0. **수정 후 예상 작동 (요약)** — 사용자가 플랜 원문을 읽지 않아도 이해되는 bullet 3~6개 (각 항목 = {무엇이} {어떻게 바뀐다}). 플랜을 사용자에게 전달할 때 이 요약을 **맨 앞**에 두고, 플랜 원문은 참고용으로 뒤에 둔다.
1. 변경 파일 목록 (최대 ~10개)
2. 접근 방식 3~5문장
3. 수용 기준 Given/When/Then 1~3개
4. 참조 문서 (사용자가 **이번 작업**에서 지정한 것만)

**예상 결과 이미지 (시각 작업 시 필수).** UI·레이아웃·연출 등 **시각적 변화**가 있는 작업이면, 승인 요청 전에 `show_widget`(visualize)으로 **예상 결과 이미지**를 요약과 함께 제시한다. 시각 변화가 없는 작업은 요약만으로 충분하다.

**승인 전 파일 수정 금지.** 예외: 사용자가 같은 메시지에 파일·방법·수용 기준을 이미 명시한 경우.

## 룰·에이전트 설정 변경 (강함)

`.claude/rules/**`, `.claude/agents/**`, `.claude/settings.json`, `CLAUDE.md` 규칙 절을 **생성·수정·삭제**하기 전:

1. 변경 초안 제시 (넣/빼, 상시 로드 여부)
2. 아래 해당 시 **승인 전 쓰기 금지:** 상시 로드 룰 변경, 고정 문서·SSOT·정답 PNG, 플레이 규칙·스모크·PASS/FAIL, 기존 룰과 중복·충돌, 요청 범위 밖 확장
3. 불명확하면 질문 — **추측으로 룰 채우기 금지**

버그 fix 후 rule 재발 방지 제안도 동일. `.cursor/**`·`AGENTS.md`는 Cursor 전용 — Claude Code에서 수정하지 않는다.

### 쓴 뒤 확인 (무한루프 없이)

룰을 쓴 뒤 **실제로 효력을 갖는지** 1회 확인한다. 방식은 강제 유형으로 갈린다 — **이 분기가 루프를 끊는다.**

- **하드 (훅·스크립트·`settings.json`):** 대표 입력으로 block/pass **오프라인 검증** + **세션 재시작 필요 여부** 명시(훅은 세션 시작 시 스냅샷 → 등록 세션 이후부터 발동) + 등록이 **조용히 막히지 않았는지** 확인(권한·자동승인 거부). 강제 지점이 코드에 있으니 확인도 실행으로 한다.
- **소프트 (가이드·절차·스타일):** **실행 테스트 없음.** ① 기존 룰과 모순 없음 ② 의도한 로드 범위(상시/온디맨드) ③ 문구 모호성 없음 — **1회 리뷰로 끝.**
- **이 절 자체는 소프트다.** 소프트 리뷰로만 검증되고 "검증을 검증"하지 않는다 → **재귀가 여기서 멈춘다.**
- 하드로 썼는데 강제가 실제로 안 걸리면(등록 차단·스냅샷 지연 등) **"소프트로만 동작 중"임을 사용자에게 보고**한다 — 조용히 넘기지 않는다.
