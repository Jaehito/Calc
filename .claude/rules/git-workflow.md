# Git 작업 규칙

> **이 파일이 SSOT.** Claude Code 전용 — `.cursor/**`·`AGENTS.md`는 읽지도 수정하지도 않는다(동기화 의무 없음).
> Cursor 전용 「인프라 자동 전파」 예외는 Claude Code에 적용하지 않는다 (모든 푸시는 명시 요청 필요).

## 커밋 메시지

- Conventional Commits 접두사(`docs:`, `feat:`, `fix:`, `chore:` 등)는 **사용하지 않는다.**
- 변경 내용을 한국어 문장으로 직접 기술한다.
- 예 (O): "AGENTS.md에 작업 정책 추가"
- 예 (X): "docs: AGENTS.md 작업 정책 추가"

### 커밋 메시지 인코딩 (한글 등 비-ASCII)

- 셸 도구로 `git commit -m`을 호출할 때 **유니코드 escape sequence(`\uXXXX` 형식)를 사용하지 않는다.**
  bash는 `\uXXXX`를 해석하지 않아 리터럴 문자열(`노션` 같은 문자)이 그대로 메시지에 저장된다.
- 안전한 전달 방법:
  - 셸 인자에 한글을 **그대로** 작성: `git commit -m "노션 동기화 룰 제거"`
  - 멀티라인이 필요하면 **임시 파일 + `-F` 옵션** 사용:

    ```bash
    cat > "$TMPDIR/msg.txt" <<'EOF'
    제목 줄

    본문 줄
    EOF
    git commit -F "$TMPDIR/msg.txt"
    ```

  - `git commit -F -`(stdin)은 일부 환경에서 동작하지 않으므로 임시 파일을 권장한다.
    `git merge -F <파일>`도 동일한 패턴을 사용한다.
- 커밋 후 `git log -1 --format="%B"` 로 메시지가 한글로 정상 저장됐는지 반드시 확인한다.
  `\u...` 형태가 보이면 즉시 사용자에게 보고하고 히스토리 정정(amend) 동의를 받는다.

## 푸시

- 사용자 메시지에 **"푸시"** 키워드가 명시적으로 있을 때만 원격에 푸시한다.
- "커밋"만 요청한 경우 → 커밋까지만 수행하고 푸시하지 않는다.

## 브랜치

- 새 브랜치 생성은 사용자가 명시적으로 요청한 경우에만 수행한다.
- 이름 형식: `cursor/<영역>/<세부이름>-<suffix>` (기존 레포 컨벤션 유지)
  - 영역을 슬래시(`/`)로 구분해 폴더 단위로 관리한다.
  - 예 (O): `cursor/docs/main-85d3`, `cursor/env/setup-612e`
  - 예 (X): `cursor/docs-main-85d3`
- Claude Code에서는 접두사·suffix가 자동으로 붙지 않으므로 **전체 이름을 명시적으로** 작성한다.

### docs 모노 전략

- **모든 문서 작업은 단일 브랜치 `cursor/docs/main-85d3`에서 진행한다.**
  - 컨셉, 캐릭터, 기타 기획 문서를 같은 브랜치에 통합 관리.
  - 인프라 변경 시 N개 브랜치에 머지하는 부담을 줄이기 위한 솔로 워크플로우 최적화.
- docs 영역을 세분화하고 싶을 때는 별도 브랜치를 만들지 말고
  `cursor/docs/main-85d3` 안의 폴더 구조(`docs/characters/` 등)로 분리한다.
- 협업자가 추가되거나 도메인이 충분히 커지면 본 전략을 재검토한다.

## 히스토리 재작성

- `git push --force`, `git commit --amend`, `git rebase` 등 히스토리 재작성은
  사용자의 **명시적 지시 시에만** 수행한다.
